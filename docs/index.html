Did this AI-written pull request weaken its tests?

An agent that cannot make a failing test pass can always make the test stop asking. CI stays green either way. AI Test Integrity Review is an open-source GitHub Action that tries to tell those two cases apart — and shows its evidence.

Apache-2.0 Jest 29–30 · Vitest 4–5 No backend · no telemetry v0.1.0-alpha.1 · alpha
Repository Install Case study: 58 merged PRs Give feedback

What it does

  • Catches high-confidence test tampering — a test gains .skip or .only, an assertion is weakened in a reviewed transformation, the test command is bypassed, or the check itself is weakened. Only these fail the build.
  • Independent red/green evidence. Each changed test is run against the previous implementation in a fresh isolated worktree: a real regression test has to fail there with a genuine assertion failure and pass on the new code.
  • Advisory review for everything uncertain — removed assertions, tests that do not discriminate, tests it could not verify, unreadable test discovery. Reported for a human, never a build failure by default.
  • Optional targeted mutation testing on the lines the pull request changed.

Your code never leaves the runner: no network calls from the analyser, no LLM, no account, no secrets required, nothing collected.

Install in three steps

1. Check compatibility first (about a minute, never fails the job)

name: Test Integrity preflight
on: workflow_dispatch
permissions:
  contents: read
jobs:
  preflight:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
        with: { fetch-depth: 0, persist-credentials: false }
      - uses: actions/setup-node@v5
        with: { node-version: 24, cache: npm }
      - run: npm ci
      - uses: muhammadmirza97/ai-test-integrity-review@v0.1.0-alpha.1
        with:
          mode: doctor

It answers SUPPORTED / SUPPORTED WITH WARNINGS / UNSUPPORTED and explains every finding, without running your tests.

2. Add the check to pull requests

name: Test Integrity
on: pull_request
permissions:
  contents: read
jobs:
  test-integrity:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
        with: { fetch-depth: 0, persist-credentials: false }
      - uses: actions/setup-node@v5
        with: { node-version: 24, cache: npm }
      - run: npm ci
      - uses: muhammadmirza97/ai-test-integrity-review@v0.1.0-alpha.1

3. Leave it unenforced while you evaluate

Do not make it a required status check yet. This is an alpha; the point is to find out whether its findings are useful, not to police merges. Pin by commit SHA for anything you do enforce.

Evidence, including the part that went badly

The first version was a strict fail-closed gate. Run against 58 merged pull requests from 15 public repositories, it turned 31 of them red and produced 7 BLOCKs — all false. That result changed the product rather than the thresholds: blocking is now limited to five high-confidence rules, everything uncertain became advisory, and two defects were fixed.

On the same 58 merged PRsStrict policyToday
Blocking findings7 (all false)0
Required check red31 (53%)11 (19%)
Remaining red checks—all ERROR from unsupported setups

Zero blocking findings on 58 pull requests bounds the false-positive rate (95% upper bound ≈ 5%); it does not prove there are none. It says nothing about recall: the corpus contained no known tampering, so how much real test-gaming this catches is unmeasured. That is why it is an alpha. Read the full story.

Supported stack

  • JavaScript / TypeScript, Jest 29–30 or Vitest 4–5
  • GitHub Actions, pull_request and merge_group, Node 22.18+ / 24.11+
  • npm, pnpm, Yarn with node-modules
  • One project directory per run; optional mutation testing with Stryker 10

Known limits

  • It does not prove a pull request correct, safe or ready to merge.
  • It does not detect whether code was written by an AI, and does not try to.
  • Real-world recall of the blocking rules is unmeasured.
  • Not supported: Yarn Plug'n'Play, Vitest browser mode, a Jest/Vitest config reachable only through the test script, multi-project runs, non-GitHub CI. Support matrix.
  • Enforcement as a required status check has not been proven end to end yet.

Tell us what happened

The alpha exists to collect evidence from real repositories doing AI-assisted development. The issue forms take a few minutes and none of them need your source code — a finding you believe is wrong is the most valuable report of all.
